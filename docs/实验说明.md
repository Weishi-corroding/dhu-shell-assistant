# 实验七 类 ShellGPT 终端智能助手

本项目选择指导书的内容二，在 Linux 管理场景中实现命令编辑和记忆助手。交付内容包括可运行源码、离线知识库、可配置模型接口、演示脚本和测试。最终实验报告需要结合本人虚拟机的真实运行截图与现象整理，不能将示例命令当作已执行结果。

## 实现方法原理

输入先经 argparse 分为普通问答、命令生成、命令解释和历史操作。程序自动读取当前目录的 `.env`，没有该文件时在源码项目中回退到 lab7 的 `.env`；系统环境变量优先。支持 `BASEURL`、`API_KEY`、`MODEL` 等别名，配置文件仅按文本解析，不执行或插值。无密钥时进入离线模式，有密钥时默认使用在线模式；显式指定的 `--offline` 或 `--online` 优先，离线模式不读取密钥文件。

离线分支使用“意图识别 + 参数槽位 + 命令模板”。`knowledge.py` 中每条 Rule 包括完整匹配的正则表达式、命令构造函数、中文说明和示例句式。比如“查找当前目录下大于100MB的文件”匹配文件大小意图，抽取 `100` 和 `M`，生成 `find . -type f -size +100M`。路径和文本通过 `shlex.quote` 引用，使空格、通配符及其他特殊字符保持参数含义。不支持的额外条件使完整匹配失败，助手会提示改用在线模式，不擅自省略条件。

在线分支通过标准库 urllib 发起聊天补全请求。系统提示词规定 Linux + Bash 目标环境和中文解释要求；用户问题作为 user 消息传入。命令生成要求返回 `command` 与 `explanation` 两个字段的 JSON，并验证字段类型、非空解释、命令长度和响应是否完整。模型回答只是一条建议，程序不会因为模型声称“安全”就执行。

命令解释分支在离线时使用 shlex 分词并检索命令/参数词典，在线时由模型解释。离线解释是词典提示，不是完整的 Bash 解析器，复杂表达式应结合 man 手册核对。

生成结果进入独立的执行检查。检查器先拒绝 shell 组合、替换、控制字符等，再用 shlex 解析参数，并逐项检查命令及参数语法。符合白名单时仍只展示；用户显式传入 `--execute`，且处于 Linux 交互终端，再输入 `EXECUTE` 才调用系统程序。子进程使用参数列表和 `shell=False`，不经过 Bash 再解释。

记忆分支使用 SQLite 持久化问答文本、命令、来源、时间和收藏标记。检索使用参数化 SQL 和字面子串匹配。交互问答的最近 6 轮上下文仅保存在内存；不会自动将历史数据库全部发送给模型。`--no-history` 禁止写入本次问答。

## 与实验环境结合

在本人已有 Linux 虚拟机中运行，优先使用前序实验留下的真实目录与普通实验文件。先执行 `whoami`、`pwd`、`cat /etc/os-release`，记录账户、实验目录和发行版。截图保留终端提示符及本人姓名首字母缩写用户名；不要为了报告更改提示符冒充其他用户。

如需要针对已有目录生成命令，可以将 README 中 `/var/log` 替换为实际目录，例如：

```bash
python3 -m lab_shell shell --offline '在 "./前序实验目录" 中查找文件 "*.conf"'
```

本仓库没有提供虚拟机里的目录内容，不假定具体文件已经存在。在线 `--context` 可以提供当前路径和目录项名称，但应先确认这些名称可发送给接口服务。

## 效果展示步骤

1. 运行 `python3 -m lab_shell shell --offline "查看磁盘使用情况"`，截图应能看到 `df -h`、中文解释及“尚未执行”。
2. 运行 `python3 -m lab_shell shell --offline "查找当前目录下大于100MB的文件"`，确认数字和单位正确映射到 `-size +100M`。
3. 运行 `python3 -m lab_shell explain --offline "ps aux | grep python"`，展示命令词典与管道说明；该步骤不会执行管道。
4. 运行 `python3 -m lab_shell chat --offline`，分别输入 `/shell 查看内存使用情况`、`/history`、`/exit`，展示连续交互及记忆。
5. 使用 `python3 -m lab_shell history` 获取真实 ID，再运行 `python3 -m lab_shell favorite ID` 和 `python3 -m lab_shell history --favorites` 展示收藏。
6. 在 Linux 交互终端运行 `python3 -m lab_shell shell --offline --execute "查看磁盘使用情况"`，核对后输入 `EXECUTE`。截图保留命令建议、确认过程及真实磁盘输出；用系统中的 `df -h` 对照。
7. 配置本人接口后运行在线问题，例如带“7天内修改”条件的文件查找，展示模型建议和解释。配置密钥过程不要截图，也不要提交 `.env`。

可用 `bash examples/demo.sh` 批量展示离线生成和历史功能。它会将演示问答保存在 `.demo-data`，不会自动执行生成的命令；收藏和实际执行需按照以上步骤单独展示。

## 验证范围与局限

自动化测试通过真实回环 HTTP 服务验证客户端请求、响应解析、错误处理和命令生成路径，并验证知识库、参数引用、执行拒绝逻辑、会话命令、SQLite 持久化与收藏。Postman 模拟另行验证实际 CLI 到本地接口的完整调用、429、500 和超时处理；模拟响应内容是固定测试数据。

开发宿主为 Windows。最终交付的测试记录见 `验证记录.md`；Linux 系统命令执行、发行版工具可用性和真实模型质量需在本人 Linux 虚拟机中验证并补充截图。程序不会虚构虚拟机执行结果。

当前离线知识库覆盖 26 个常见句式，不支持任意自然语言推理；在线能力依赖服务商、网络和账户权限。部分工具如 `free`、`ip`、`ss`、`systemctl` 取决于 Linux 发行版和安装情况。执行白名单有意保守，不能替代隔离环境、权限控制或人工审查；只读操作也可能读取敏感数据。后续可按实际实验需求扩展 Rule 和解释词典，执行白名单需要独立审查后才扩展。
