## Postman 接口模拟

启动：

```text
postman simulation run postman/simulations/assistant.sim.yaml --port 4900 --output ndjson --no-history
```

验证：

```text
python -m tests.postman_smoke
Ran 3 tests
OK
```

实际 CLI 对 `/llm/chat/completions` 发出 POST，返回 200，解析得到 `df -h`；不符合协议的空请求返回 400。请求事件中记录了真实调用的方法、路径和状态。429、500 和延迟通过各模拟成员的条件注入，测试确认客户端报错及超时；这些注入错误不会作为成员请求事件记录，这是模拟器的日志行为。

模拟服务已在验证后通过 SIGINT 停止。退出汇总显示 1 次成功请求和 1 次失败请求，不包含注入条件的调用。mock 基于仓库内 `postman/chat-contract.json` 的官方协议子集生成，并追加请求校验；没有使用或声称检索到服务商自有 mock。

## 用户配置的真实接口验证

2026 年 10 月 21 日，程序使用用户提供的 `.env` 中的 `BASEURL`、`API_KEY` 配置。未将密钥写入记录，也未修改用户的 `.env`。接口为 DeepSeek，`GET /models` 成功返回 `deepseek-flash` 和 `deepseek-v4-pro`，与默认模型 `deepseek-flash` 一致。

使用实际 CLI 执行 `python -m lab_shell shell --online --no-history --json "查看磁盘使用情况"`，`POST /chat/completions` 返回 HTTP 402，因此没有取得模型回答，也没有执行任何生成命令。按照 [DeepSeek 官方错误码说明](https://api-docs.deepseek.com/quick_start/error_codes/)，402 表示账户余额不足。程序已增加对应中文提示。需账户余额问题解决后再验证真实回答质量。
